# solana-mcp-webmcp

A Solana MCP server for the **Web MCP era** — one deployment that combines:

- **Solana docs intelligence** in the design of the official `solana-mcp` (Databricks-backed corpus; see the upstream repo for the ingestion side),
- **an AI gateway inside the server** (Neon AI Gateway) — `solana_ask` answers Solana questions in-server, so MCP clients need no model key of their own,
- **MCP Apps UI** — a `ui://` Docs Explorer widget linked from a decoupled render tool,
- **WebMCP** — the landing page registers tools with `navigator.modelContext` for browser agents,
- **real auth** — Neon Auth JWTs verified against the published JWKS (EdDSA), a `whoami` profile tool, and RFC 9728 protected-resource metadata,
- **storage & data** — Neon S3-compatible object storage with presigned URLs, plus Neon Data API / Postgres configuration.

## Tools

| Tool | Auth | What it does |
| --- | --- | --- |
| `solana_ask` | anonymous | Solana Q&A generated by the built-in gateway |
| `ai_models` | anonymous | List gateway models (63 on the reference deployment) |
| `ai_chat` | Neon Auth (`solana:ai`) | General gateway chat |
| `whoami` | Neon Auth | Profile tool — stable opaque user id (`openai/profile`) |
| `render_docs_explorer` | anonymous | Render search/section results in the Docs Explorer widget |
| `storage_put_text` | Neon Auth (`solana:write`) | Store a text object in S3, get a presigned URL |

Anonymous tools declare `securitySchemes: [{type: "noauth"}]`; authenticated tools declare `oauth2` scopes and return an `mcp/www_authenticate` challenge when the token is missing or invalid.

## One-shot deployment

```bash
cp .env.example .env   # fill in the secrets (gateway token, S3 keys, DATABASE_URL, Databricks)
docker build -t solana-mcp-webmcp .
docker run --env-file .env -p 8080:8080 solana-mcp-webmcp
# MCP endpoint: http://localhost:8080/mcp   Landing page + WebMCP: http://localhost:8080/
```

Local dev without Docker:

```bash
pnpm install
cp .env.example .env
pnpm dev
pnpm inspector   # MCP Inspector against http://localhost:8080/mcp
```

Deploy targets: the Docker image runs anywhere containers run (Cloud Run, Render, Fly.io, Railway). Set `PUBLIC_BASE_URL` to the public origin so auth challenges and protected-resource metadata point at the right host.

## Configuration

All configuration is environment variables — see [`.env.example`](./.env.example) for the full list with the reference deployment's non-secret values filled in. Secrets (gateway token, S3 secret key, database password, Databricks token) are **never** committed; `.env` is gitignored.

Notes from wiring the reference deployment:

- Neon Auth publishes its JWKS at `JWKS_URL` (verified: EdDSA, one key). The Data API requires a Neon Auth JWT bearer — anonymous Data API calls return `missing authentication credentials` by design.
- Node's `pg` driver does not support SCRAM channel binding: the deployed `DATABASE_URL` should omit `channel_binding=require`.
- Neon storage requires `forcePathStyle: true` on the S3 client.

## Architecture

```
server/index.ts   node:http host — statics (landing page, webmcp.js), /health,
                  /.well-known/oauth-protected-resource, everything else → MCP
lib/index.ts      createMcpHandler factory — registers tools (_meta passthrough)
                  and the ui:// docs-explorer resource (text/html;profile=mcp-app)
lib/tools.ts      the tool registry (data tools decoupled from the render tool)
lib/gateway.ts    Neon AI Gateway client (OpenAI-compatible /v1/models, /v1/chat/completions)
lib/auth.ts       Neon Auth JWT verification via remote JWKS (jose)
lib/storage.ts    S3 put + presigned GET
lib/ui.ts         the Docs Explorer widget (single-file HTML, zero external requests)
public/webmcp.js  WebMCP registrations for browser agents (guarded, never throws)
```

## Status / honesty

Verified live against the reference Neon project on 2026-11-05: AI Gateway model catalog (63/63 enabled), JWKS (200, EdDSA), Data API (auth-required response as designed), and the S3 round-trip (create `assets` bucket → put → presigned GET byte-exact). The Databricks docs-search wiring follows the upstream solana-mcp design and activates when `DATABRICKS_*` are set; without them the gateway tools still work.
